# Implementation notes

- Runtime floor: PHP 8.2. Readonly classes and enums are used; the SDK does not require PHP 8.5.
- JSON Schema: `opis/json-schema` 2.6 or compatible 2.x. The upstream project documents Draft 2020-12 support and support for all keywords in supported drafts. PASP schemas use `const`, `$ref`, `format`, and standard object/array/numeric keywords. The validator receives objects decoded as `stdClass`, preserving `{}` versus `[]` and numeric types. Its documented Draft 2020-12 support covers `$defs`, `prefixItems`, `dependentRequired`, and `unevaluatedProperties`; the package tests exercise representative schemas when run.
- Canonical references: bundled schema references are expanded against packaged schema files. The resolver rejects every non-fragment reference on caller-provided schemas, so HTTP, HTTPS, file, and other external resolution is unavailable and validation makes no network requests.
- UTF-8 and JSON: `json_decode` uses `JSON_THROW_ON_ERROR`; a UTF-8 validity check runs first. Big integers are retained as strings instead of overflowing PHP integers. Malformed manifest JSON maps to `PASP_INVALID_MANIFEST`; malformed resource records map to `PASP_INVALID_RECORD`.
- Resource streaming: each NDJSON line is parsed/validated independently while raw line bytes are added to a SHA-256 context and byte count. Blank lines are ignored as records while still counted and hashed. A final line without LF is processed. The current record is the only record-sized buffer.
- Assets: the asset index is read line by line, retaining only one descriptor; asset bytes use 8 KiB binary stream reads. Digest and count use bytes actually read. Descriptor totals are scalar counters.
- Paths: protocol paths reject empty/dot/traversal segments, NUL, leading slash/tilde, drive prefixes, and backslashes (including UNC and mixed-separator forms). Existing resolved paths must stay beneath the real bundle root. Opened data must be regular files. Reparse points/junctions are protected through `realpath` containment where PHP exposes their resolved target.
- Filesystem limitation: containment is checked with `realpath` before a separate `fopen`; portable PHP does not provide race-free open-under-directory semantics. A concurrent path replacement creates a TOCTOU window. The implementation does not claim race-free protection.
- Packaging: schemas are copied byte-for-byte from `protocol/pasp/v1/schemas` to `resources/schemas`; runtime paths are package-local. `composer.json` omits a version so tags determine releases. `.gitattributes` excludes test and development files from archives.
- Monorepo split: keep `sdk/php` canonical. From the monorepo, run `git subtree split --prefix=sdk/php HEAD` and record the resulting commit ID. Review it with `git show --stat <split-commit>`. In a checkout of the release repository, sync it to the root branch with `git push <release-remote> <split-commit>:refs/heads/main`; repeated splits retain subtree history, so later updates can be pushed as fast-forwards. Run `composer validate --strict`, `composer install`, PHPUnit, and the archive consumer proof from that repository. After review, create tag `v0.1.0` at the split commit in the release repository and push that tag when separately authorized. Register `openexit/openexit` with Packagist and configure its source update hook. The split repository must have this package's `composer.json` at its root. No split, remote push, tag, or publication is performed by the SDK build.
- Platform notes: paths are checked against both POSIX and Windows syntax on every platform. Symlink/junction tests require appropriate Windows privileges and filesystem support.
